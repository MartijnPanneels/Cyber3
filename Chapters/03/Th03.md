**What are the essential elements to configure SSH properly:**
**Logging in remotely using keys instead of user/password, authorized_keys file, known-hosts file**

    You need a key-pair. A private and public key.

    authorized_keys → which clients are allowed to log in to the server.
    known_hosts → which servers are trusted by the client.

**SSH config for client and server**


_Example of server config:_

```
Port 22

PasswordAuthentication no
PubkeyAuthentication yes

AuthorizedKeysFile .ssh/authorized_keys

AllowUsers vagrant

HostKey /etc/ssh/ssh_host_rsa_key
HostKey /etc/ssh/ssh_host_ecdsa_key
HostKey /etc/ssh/ssh_host_ed25519_key
```

**The difference between a passphrase on a key vs user/password**

A passphrase protects your private SSH key on your local machine. (ssh-keygen -t)

A user/password are basic login credentials. Password checked in (/etc/shadow)

**What is meant by a Jump/Bastion host and why would a company use this?**

It is a highly controlled and hardened server that acts as a single entry point of a private network.

Instead of exposing all internal VMs to the internet, only one hardened server is reachable.

**What is the difference between local and remote port forwarding using SSH? You should be able to explain the difference using a proper use case.**

Local (-L): you open a port on your local machine and forward it to a remote service. `ssh -L <local_port>:<remote_host>:<remote_port> user@ssh-server`

Remote (-R): you open a port on the remote server and forward it to a service running on your local machine. `ssh -R <remote_port>:<local_host>:<local_port> user@ssh-server`

**What is the SOCKS protocol conceptually and give an example where or when this might be interesting.**

SOCKS (-D): It lets you route any app’s traffic through another host without exposing services directly or rewriting network code. (Application-level proxy L7)

Extra info: SOCKS vs VPN

| Feature                | SOCKS Proxy                        | VPN                                    |
| ---------------------- | ---------------------------------- | -------------------------------------- |
| **Scope of traffic**   | Only apps you configure use it     | _All_ traffic on the machine is routed |
| **Network layer**      | Application-level proxy            | Network-level tunnel                   |
| **Setup required**     | No extra software (SSH only)       | Client software + admin rights         |
| **Permissions needed** | Usually only SSH access to a host  | Requires VPN server infrastructure     |
| **Security**           | Encrypted if via SSH               | Encrypted tunnel for all traffic       |
| **Typical use**        | Quick access to specific resources | Full remote-work network integration   |

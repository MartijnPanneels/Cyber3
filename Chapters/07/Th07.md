### 1\. What is a SIEM?

**SIEM** stands for **Security Information and Event Management**.

It is a software solution that aggregates and analyzes activity from many different resources across your entire IT infrastructure. Think of it as the "brain" of your security ecosystem.

-   **How it works:** It collects logs from firewalls, servers, routers, and applications. It normalizes these logs (puts them in a standard format) and looks for correlations (patterns) that indicate a threat.
-   **Examples:**
    -   **Splunk** (Industry standard, very powerful)
    -   **Microsoft Sentinel** (Cloud-native)
    -   **IBM QRadar**
    -   **Elastic Security (ELK Stack)**
    -   **Wazuh** (Open-source)

### 2\. What is a SOC?

**SOC** stands for **Security Operations Center**.

While a SIEM is a _tool_, a SOC is a **facility (or team)**. It consists of the people, processes, and technology responsible for monitoring, analyzing, and defending an organization's information systems.

-   **The Goal:** To detect, analyze, respond to, and report on cybersecurity incidents in real-time.

### 3\. Compliance in Cybersecurity

**Compliance** refers to adhering to standards, regulatory requirements, and laws regarding data protection.

-   **Meaning:** It isn't just about being secure; it is about _proving_ you are secure according to a specific checklist.
-   **Examples:**
    -   **GDPR:** Protecting EU citizens' data.
    -   **PCI-DSS:** Protecting credit card information.
    -   **HIPAA:** Protecting medical records.
-   **Role:** Security tools (like SIEMs) often have "Compliance Modules" that generate reports to show auditors that specific security controls (like password policies or file monitoring) are active.

### 4\. What features does Wazuh offer?

Wazuh is an open-source security platform that unifies XDR (Extended Detection and Response) and SIEM capabilities.

-   **Log Analysis:** Centralizes logs from operating systems and applications.
-   **File Integrity Monitoring (FIM):** Detects changes in critical files.
-   **Intrusion Detection (HIDS):** Host-based intrusion detection to find rootkits or malware.
-   **Vulnerability Detection:** Scans installed software to find known vulnerabilities (CVEs).
-   **Configuration Assessment:** Checks if systems are configured securely (e.g., checking if SSH root login is disabled).
-   **Active Response:** Can automatically block an IP or stop a process when a threat is detected.

### 5\. What is FIM?

**FIM** stands for **File Integrity Monitoring**.

It is a technology that monitors specific files on a system to see if they change.

-   **How it works:** It calculates a "hash" (a digital fingerprint) of a file. If the file is modified, the hash changes, and FIM alerts the admin.
-   **Use Case:** If a hacker modifies a system configuration file or replaces a legitimate system binary (like `notepad.exe`) with a virus, FIM will detect it immediately.

### 6\. What is Sysmon?

**Sysmon** (System Monitor) is a Windows system service and device driver that is part of the Sysinternals suite (Microsoft).

-   **Function:** It provides detailed information about process creations, network connections, and changes to file creation time.
-   **Why use it?** Standard Windows Event Logs are often insufficient for deep forensic analysis. Sysmon provides the granular detail needed to hunt down advanced threats.

### 7\. IDS vs. IPS

The difference lies in the **action** taken.

-   **IDS (Intrusion _Detection_ System):**
    -   **Passive:** It watches traffic like a security camera.
    -   **Action:** If it sees an attack, it sends an **Alert**, but it does _not_ stop the traffic.
-   **IPS (Intrusion _Prevention_ System):**
    -   **Active:** It sits in the line of traffic like a security guard.
    -   **Action:** If it sees an attack, it sends an Alert **AND Blocks** the traffic immediately.

### 8\. Firewall vs. IDS/IPS (Conceptual Difference)

-   **Firewall (The Bouncer):**
    -   Looks at **Metadata** (IP addresses, Ports, Headers).
    -   _Logic:_ "Is this person on the guest list?" (Is Port 80 allowed from this IP?).
    -   Generally does not look deep inside the packet.
-   **IDS/IPS (The Investigator):**
    -   Looks at the **Payload/Content** (Deep Packet Inspection).
    -   _Logic:_ "This person is on the guest list, but are they carrying a knife?" (Is there a SQL Injection code inside this allowed HTTP packet?).

### 9\. Basic Suricata Rules

Suricata is a popular network threat detection engine. Rules usually follow this syntax:
`action protocol source_ip source_port -> dest_ip dest_port (options)`

**Rule A: Detect specific protocol (e.g., ICMP/Ping)**
This rule alerts if anyone from inside the network ($HOME_NET) pings an external server.

```bash
alert icmp $HOME_NET any -> $EXTERNAL_NET any (msg:"ICMP Ping Detected Outbound"; sid:1000001; rev:1;)
```

**Rule B: Detect traffic on a specific port (e.g., SSH on port 22)**
This rule alerts on any TCP traffic attempting to connect to port 22.

```bash
alert tcp any any -> $HOME_NET 22 (msg:"SSH Connection Attempt"; sid:1000002; rev:1;)
```

### 10\. Physical IDS/IPS: Placement and Impact

**Where to place it?**
Ideally, you place it **behind the firewall** (between the Firewall and the Core Switch).

-   _Why?_ You only want to inspect traffic that the firewall allowed through. If you put it in front of the firewall, the IDS/IPS will waste resources analyzing noise that the firewall would have blocked anyway.

**How to set it up?**

-   **For IDS (Passive):** You use a **SPAN Port** (Port Mirroring) on your switch or a **Network TAP**. This sends a _copy_ of the traffic to the IDS.
    -   _Network Impact:_ **Zero.** Since it is looking at a copy, if the IDS crashes, the network keeps working.
-   **For IPS (Active):** You must set it up **Inline** (Cable A goes into IPS, Cable B goes out to Switch). The traffic physically passes _through_ the device.
    -   _Network Impact:_ **High Risk.** It introduces latency (processing time). If the IPS device loses power or crashes, the network link is broken (unless it has a "fail-open" feature).

### 11\. What is Security Onion?

**Security Onion** is a free and open-source Linux distribution (OS) built specifically for **Network Security Monitoring (NSM), log management, and threat hunting.**

-   **The Goal:** To provide a complete, pre-configured toolkit to help you "peel back the layers" of your network traffic to see what is actually happening.
-   **Explanation:** instead of installing Suricata, then installing Zeek, then installing Wazuh, and trying to make them talk to each other, you install Security Onion. It bundles all these tools (Snort/Suricata, Zeek, Wazuh, Kibana, CyberChef) into one cohesive platform with a unified dashboard.

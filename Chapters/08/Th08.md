### **1. The Fundamental Goal of IPsec**

The fundamental goal of **IPsec (Internet Protocol Security)** is to protect data flows between two points over an unsecured network (like the public internet). It transitions the Internet Protocol (IP) from a "best-effort" delivery system into a secure delivery system.

It achieves this by guaranteeing the **CIA Triad** plus one additional feature at the Network Layer (Layer 3):
* **Confidentiality:** Encrypting data so no one in the middle can read it.
* **Integrity:** Ensuring data has not been altered in transit (hashing).
* **Authentication:** Verifying the identity of the sender (signatures/certificates).
* **Anti-Replay:** Preventing hackers from capturing packets and resending them later to trick the system.

---

### **2. How IPsec Works: SPs and SAs**

IPsec operates by intercepting IP packets and applying security transformations based on a database of rules and active "contracts."

#### **SP (Security Policy)**
The **Security Policy (SP)** is the **"Rule Book."** It is a database configured by the administrator that tells the device *what* to protect.
* **Function:** It looks at traffic selectors (Source IP, Destination IP, Port, Protocol) and decides an action: **Protect** (apply IPsec), **Bypass** (allow cleartext), or **Discard** (drop).
* **Example:** "All traffic from HQ (192.168.1.0) to Branch (10.0.0.0) must be encrypted."

#### **SA (Security Association)**
The **Security Association (SA)** is the **"Active Contract."** Once the SP says "protect this traffic," the device looks for an active SA.
* **Function:** An SA is a set of active technical parameters agreed upon by both devices. It contains the specific encryption keys, algorithms (e.g., AES-256), and the **SPI (Security Parameter Index)** used to track the connection.
* **Simplex Nature:** SAs are **one-way**. For a two-way conversation, you need two SAs (one inbound, one outbound).

**The Workflow:**
1.  **Packet Arrives:** The router looks at its **SP**.
2.  **Decision:** If the SP says "Encrypt," the router checks if an **SA** already exists.
3.  **Negotiation:** If no SA exists, the router triggers **IKE** (Internet Key Exchange) to negotiate a new SA.
4.  **Transmission:** The data is processed using the keys in the SA and sent.

---

### **3. IPsec Modes: Transport vs. Tunnel**

IPsec can package data in two ways depending on your infrastructure needs.



| Feature | **Transport Mode** | **Tunnel Mode** |
| :--- | :--- | :--- |
| **What it encrypts** | Only the **Payload** (The data inside the IP packet). | The **Entire Packet** (Header + Payload). |
| **IP Headers** | Keeps the original IP header. | Adds a **New IP Header** on top of the encrypted packet. |
| **Primary Use** | **Host-to-Host** (e.g., Server to Server for encrypted Telnet). | **Site-to-Site VPNs** (e.g., Firewall to Firewall). |
| **Overhead** | Lower (less headers added). | Higher (adds new IP header). |

---

### **4. The Protocols: AH and ESP**

These are the actual languages IPsec uses to format the packet. You can use them separately or together (though they are rarely used together anymore).

#### **AH (Authentication Header)**
* **Protocol Number:** 51
* **What it does:** Provides **Integrity** and **Authentication**. It "signs" the entire packet (including the header) to prove it wasn't tampered with.
* **What it lacks:** **It offers NO Encryption.** The data is readable in plain text.
* **The Problem:** Because it hashes the IP header, it breaks **NAT** (Network Address Translation). If a router changes your IP address (NAT), the AH signature fails.

#### **ESP (Encapsulating Security Payload)**
* **Protocol Number:** 50
* **What it does:** Provides **Confidentiality (Encryption)**, **Integrity**, and **Authentication**.
* **How it works:** It surrounds the payload with a Header and a Trailer.
* **NAT-Friendly:** Because it typically encrypts the payload but leaves the outer IP header unsiged (in Tunnel mode), it works better with NAT (especially when used with NAT-Traversal, which wraps ESP in UDP port 4500).

> **Note:** Modern VPNs almost exclusively use **ESP** because confidentiality (encryption) is usually the primary requirement.

---

### **5. What is IKE?**

**IKE (Internet Key Exchange)** is the negotiator. Before IPsec can send encrypted data (AH or ESP), the two devices need to agree on keys. Doing this manually is impossible at scale, so IKE automates it.

IKE runs on **UDP Port 500** and operates in two phases:

1.  **Phase 1 (The Handshake):** The devices authenticate each other (using Pre-Shared Keys or Certificates) and set up a secure, encrypted management channel.
2.  **Phase 2 (The Setup):** Inside that secure channel, they negotiate the actual IPsec SAs (which algorithms to use for the data).

**Why is IKE important?** It creates the "Security Association" (SA) dynamically. Without IKE, you would have to manually type encryption keys into both routers every time a session expired.
